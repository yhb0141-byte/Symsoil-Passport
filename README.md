# 共壤 Passport

一张社区身份卡，一个明确确认的入口，一本社区积分账本。

这是可本地运行的第一版实现：浏览器演示三按键随身卡，Node.js 服务核验回复签名，SQLite 持久化积分和授权。NFC 写入账户入口、读取后发起具体单据；成员看清内容并长按确认后，积分才入账或扣除。

## 立即试用

需要 **Node.js 24 或更新版本**。运行服务不需要安装第三方依赖。

```sh
git clone https://github.com/yhb0141-byte/Symsoil-Passport.git
cd Symsoil-Passport
git switch feat/passport-mvp
npm run demo
```

打开 <http://127.0.0.1:8787>，点击「开启本地试用」。

1. 打开「运营终端」，核定一笔贡献，例如菜园维护 30 积分。
2. 点击「模拟 NFC 碰一碰」。随身卡会显示具体单据、分值和预计余额。
3. 短按 OK 选择回复，再短按进入确认页，**长按 OK 两秒**提交。短按或提前松手不记账。
4. 新建「菜园收获包」兑换单，再碰卡并确认，扣除 20 积分。重复碰同一单不会重复扣分。
5. 未交付的兑换可按原交易发起退回；成员确认后返还积分。交付记录与退回互斥。

试用起始余额为 100 积分。试用模式只监听本机，并显式提供四种角色的试用凭证。试用账本与普通模式分别保存；不要把试用模式反向代理到公网。

独立运营入口：<http://127.0.0.1:8787/operator.html>。核定人或兑换终端使用自己的角色凭证进入，无需持有成员凭证。核定人可创建成员、签发限时入口、撤销凭证与办理失物换机；兑换终端只管理自己的单据。

## 已实现

| 功能 | 行为 |
| --- | --- |
| 随身确认卡 | 上、下、OK 三键界面；选择语义后长按提交；提前松手取消 |
| 社区积分写入 | 核定贡献 → NFC 关联成员 → 成员明确领取 → 账本入账 |
| NFC 刷出积分 | 建立固定价格兑换单 → 碰卡 → 成员确认扣除 → 登记交付 |
| 原单退回 | 关联未交付的原扣分记录；整笔退回一次，保留原记录 |
| 转述许可 | 表达准确、需要修改、仅保留原话、不允许转述分别保存 |
| 工具借用 | 独立记录承担这次借用的明确回复 |
| 小壤有限授权 | 精确内容、菜园排班资源、24 小时、最多一次；可撤销 |
| 版本与回执 | P-256 签名绑定完整内容摘要、版本、成员、设备、挑战和计数器 |
| 持久化与核验 | SQLite 事务和不可修改流水；导出 JSON 后核验签名及积分算术 |
| 多人入会 | 新成员起始积分为零，分别持有独立成员凭证 |
| 凭证发放与撤销 | 访问入口默认7天有效；只显示一次，数据库保存哈希；核定人可撤销 |
| 失物与换机 | 旧设备、旧卡、旧成员凭证与未使用授权同时停用；新入口登记新设备 |
| 断线恢复 | 原签名发送前保存在设备；结果未知时核对同一笔，重试不再批准或记账 |

查看、碰卡和沉默都不会产生同意。积分兑换与其他议题独立；积分不影响基本公共服务、表达权或治理权限。本版没有人民币充值、现金提现或积分转账。

## NFC 与实际硬件

普通可写 NDEF 标签只保存 `sp:1:<随机账户引用>`。标签里没有积分余额、姓名、访问凭证或签名私钥。余额以社区本地账本为准，复制或改写标签不能完成扣分。

「用 NFC 读卡」「用 NFC 写入账户入口」已接入 Web NFC；浏览器会在支持的安全环境中请求 NFC 权限。不支持的浏览器会禁用这两个按钮，模拟碰卡仍可体验完整流程。真实 NFC 收发尚未经过实物测试。

**当前确认设备是浏览器。** FoloToy 工牌固件、BLE 传输、桌面 USB 读卡器和安全 NFC 卡钱包尚未实现。使用工牌现有的被动标签时，读写需要外部读卡端；本版没有把余额写入标签来充当离线钱包。

见 [硬件接入约定](firmware/README.md)、[API 与协议](docs/api.md) 和 [Web NFC 官方说明](https://developer.chrome.com/docs/capabilities/nfc)。

## 普通本地模式

```sh
npm start
```

起始积分为 0，没有公开试用登录接口。首次启动生成 `data/local/access.json`，仅本机运营者可读取。核定人用其中的 `admin.token` 登录 `/operator.html`，在「成员与设备」创建成员并签发入口，再将该成员的凭证交给对应持有人。成员在首页输入自己的凭证即可。

| 角色 | 权限 |
| --- | --- |
| `member` | 自己的事项、积分、回执、设备登记和授权撤销 |
| `admin` | 核定贡献、发起退回、发布或修改事项、停用设备 |
| `terminal` | 创建自己的兑换单、读取 NFC、查看自身单据交付状态、登记交付 |
| `agent` | 执行获准的具体单次排班更新 |

本版预置示例成员 M-017「菡白」和隔离测试成员 M-018，也支持核定人创建更多成员。正式身份核验仍需在社区入会时完成。新增入口默认7天有效，小壤默认24小时，可设为1–720小时；初始本机凭证用于引导设置，无自动到期，建议完成替代入口发放后撤销。凭证原文只在签发时显示，列表无法找回；撤销后的初始凭证不会在重启时恢复。

访问凭证存放在当前页面内存中，刷新后需重新进入；浏览器设备密钥保存在 IndexedDB。换机须先由核定人停用旧设备并重新签发成员入口。原浏览器使用新入口进入时会生成新设备密钥，历史积分和回执保留。

成员收件箱和独立运营终端每3秒自动更新；隐藏页面暂停，返回或恢复连接时核对最新记录。同步保留正在阅读的内容和未提交的表单。事项改版、关闭或过期会取消长按并要求重新查看；自动同步不会生成回复签名。仍可手动刷新，网络失败时会显示连接提示。

提交时若连接中断，界面会区分「服务端未接受」与「结果待核对」。不要据网络错误推断没有记账。重新进入后，设备恢复原签名：已存在相同回执时直接核对，尚未送达时可点击「核对同一笔提交结果」重发；不会自动生成新批准。未核对完之前不会再签发另一笔回复。

可通过环境变量设置 `PASSPORT_PORT`、`PASSPORT_DATA_DIR`。普通模式如需在局域网访问，可设置 `PASSPORT_HOST`；手机访问 Web NFC 需要 HTTPS，可在反向代理后设置精确的 `PASSPORT_ORIGIN=https://你的域名`。该配置只提供传输和来源校验，仍需完成正式部署的身份、运维和硬件验证。

不要把 `data/`、访问凭证或个人导出记录提交到仓库。备份应包含完整 SQLite 数据库；服务运行中用 SQLite 的一致性备份方法，或停止服务后复制整个数据目录。

## 验证

```sh
npm run check
npm test
```

测试覆盖权限隔离、签名伪造、旧版本与过期回复、重放、重复碰卡、余额与库存不足时回滚、原单退回、授权越界与撤销、数据库重开及导出核验。GitHub Actions 在分支提交和 Pull Request 上运行这些检查。

可选的完整浏览器检查：

```sh
npm install --no-save playwright
npx playwright install chromium
npm run test:ui
```

界面检查使用独立临时账本，覆盖短按与长按、入账与扣分、退回、交付、版本更新、授权、导出、刷新后恢复、独立运营、两个成员的余额隔离、入口签发和失物换机、无需手动刷新的收件箱与设备状态、阅读内容保留、长按改版取消、过期提示、退出后的迟到响应隔离，以及 320 像素的窄屏布局。截图输出到忽略的 `test-results/ui/`。已有 Chrome 时可设置 `PASSPORT_BROWSER_BIN` 为可执行文件路径。

核验自己的导出文件：

```sh
npm run verify-export -- /path/to/symsoil-passport-M-017.json
```

核验的是提供的公钥下的回复签名、内容绑定与流水一致性；不证明持有人身份、签发方可信、导出完整性或当前撤销状态。

真实工牌移植可先运行 `npm run test:protocol`。固定的合成协议材料及独立 Python 验证说明见 [协议向量](firmware/protocol-vectors/README.md)。它们验证编码和签名兼容性，不是已完成的工牌固件或实物验证。
