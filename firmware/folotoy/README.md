# FoloToy AI Passport 硬件验收固件

这里保存的是基于 FoloToy 官方 BSP 的**可重复应用覆盖层**，不是完整上游副本。它锁定官方 `main` 提交 `33d3d1d93a1125b356b47b6d83a7a60121be801e`，目标为 ESP32-C3、8 MB Flash、无 PSRAM、ST7789P3 240×320 屏幕，以及 GPIO0 ADC 电阻梯上的 UP / DOWN / OK 三键。

当前增量用于验证随身确认卡最容易被错误实现的物理语义：

- 打开事项只进入阅读页，不产生同意。
- 贡献入账、积分扣除、原单退回、任务承担、转述许可和有限授权具有独立回复集合。
- 选择回复后仍须进入最终复核页；短按 OK、沉默或长按其他键都不会请求签名。
- 只有连续按住 OK 两秒产生 `SIGNATURE_READY` 事件。
- 事项到期或正文摘要/版本变化会关闭旧事项，之后的长按无效。

设备页面采用独立的森林绿、米白和日光黄界面，没有复用官方硬件测试菜单。右上角读取可用电量。当前只载入一条明确标注的合成贡献事项；两秒长按只写入串口验收日志，**不会生成私钥、签名、联网或改动社区账本**。这样可以先在真实设备上验证屏幕、按键电压、提前松手和两秒手感，再接入 BLE、密钥存储及服务端挑战。

覆盖层同时移植了 `symsoil-passport/1` 精确确认帧编码和公开合成向量。启动 UI 前会运行四组确认自检：按固定字段顺序生成 UTF-8 canonical JSON，核对事项正文 SHA-256，验证 IEEE P1363 格式的 P-256 签名，并确认计数器变化后原签名失效。另有一组 `symsoil-delivery-result/1` 自检，验证社区服务最终结果绑定原成员签名、请求和传输号，且篡改结果后签名失效。自检失败会停在进入 UI 之前。公开向量不含私钥，也不代表固件已经能够签名或已配置真实服务信任锚。

覆盖层还包含尚未接入 UI 的回执交付层：双槽 NVS 日志保存一笔已签名、结果待核对的公开回执；新回执不能覆盖旧回执，完全相同的重试不会再次写 Flash。版本化传输封装可按链路包长分片，错误 ACK、超时与重连只重发同一片，并限制单次连接重试次数。协调器保证先持久化再发送，重启后恢复完全相同的首包；分片全部送达仍保留回执。唯一公开清除入口会重建服务结果canonical帧、用传入的社区P-256公钥核验服务签名，再匹配社区、传输号和原64字节成员签名。CRC只是损坏检测；实际使用仍需要可信公钥配置与认证 BLE 会话。

## 主机逻辑测试

```sh
./firmware/folotoy/test-host.sh
```

测试覆盖全部六类事项的不同语义、早松手、沉默、错误按键、两秒确认事件、改版失效和到期边界；同时逐字节核对四组 canonical 确认帧和一组服务签名结果帧。交付层测试注入首槽/镜像写入失败、双槽损坏、重复保存、未核对覆盖、错误 ACK、超时、断线和掉电重启；还验证分片完成不清除、错配结果不清除、结果丢失后原字节重发及匹配结果清除。主机测试不链接 ESP-IDF mbedTLS 或真实 NVS，因此设备端摘要、签名与 NVS 自检只经过交叉编译，尚未在工牌上执行。

## 应用到官方完整项目

```sh
git clone https://github.com/FoloToy/ai-passport.git
git -C ai-passport checkout 33d3d1d93a1125b356b47b6d83a7a60121be801e
./firmware/folotoy/apply-overlay.sh /absolute/path/to/ai-passport
```

脚本只接受完全匹配的干净上游提交：它把官方 BSP 的长按阈值改为 2000 ms，并替换 `main/` 应用入口；有本地修改时拒绝覆盖。随后按官方要求使用 ESP-IDF 5.5.3：

```sh
source /path/to/esp-idf-v5.5.3/export.sh
cd /absolute/path/to/ai-passport
./tools/validate.sh --firmware
```

构建成功只表示固件可编译。未经明确同意不要刷机；`full.bin` 从 `0x0` 写入会替换现有固件，并可能重置 NVS 数据。

本仓库覆盖层已在 ESP-IDF 5.5.3 下完成交叉编译：应用镜像 666,336 字节，合并镜像 731,872 字节，官方 `validate.sh --firmware` 的分区与合并镜像检查通过。构建工件不提交仓库；这些数字只证明当前源码和 mbedTLS 验证路径能生成 ESP32-C3 镜像，不代表启动自检或工牌实测通过。

## 实物验收清单

1. 设备启动后不出现官方硬件测试菜单，直接进入共壤收件箱。
2. 屏幕方向、圆角、配色、正文换行和右上角电量没有遮挡。
3. 三键逐一测量 ADC 电压：UP `[0,150)` mV、DOWN `[150,447)` mV、OK `[447,1900)` mV；不同电量下仍不串键。
4. 阅读、短按 OK、提前松手、长按 UP/DOWN均不产生验收事件。
5. 最终复核页连续按住 OK 两秒才出现结果页；串口只记录合成事件，账本保持不变。
6. 连续操作、返回和超时没有重启、看门狗、对象泄漏或按键卡死。

## 尚未实现

- P-256 私钥生成与保护、设备登记和确认帧签名；当前只实现公开向量验证。
- 交付协调器与真实签名/UI工作流的连接；认证 BLE 配对、GATT 驱动、超时调度和成员凭证交付。当前协调器已连接 NVS 与分片状态机，但尚无真实链路调用它。
- 定义社区服务公钥的安全配置、轮换、停用和恢复流程，再让真实 BLE 接收路径调用已完成的签名结果清除入口。合成结果向量不能作为生产密钥。
- 中文字体子集与真实成员姓名、动态事项的缺字处理。
- NTAG213 没有 MCU BSP 接口；NFC 仍由外部终端读取，标签只保存账户引用。
- 真实工牌、真实 NFC 标签、RF、功耗和低电量测试。
