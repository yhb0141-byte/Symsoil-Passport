# 真实工牌接入约定

此目录是接入说明，**没有已完成的 FoloToy 固件、BLE 服务或 USB 读卡器驱动**。当前可运行设备是浏览器三按键演示，后端协议与签名核验已经实现。

可先用 [固定协议向量](protocol-vectors/README.md) 校验移植代码：四种事项的内容摘要、完整帧、公钥和P1363签名已经过 Node 与独立 Python 验证，材料不含私钥或真实凭证。

## 角色分工

| 部件 | 职责 |
| --- | --- |
| 工牌屏幕与三按键 | 展示完整事项、选择明确语义、物理长按后签名 |
| 工牌设备密钥 | 每台设备一对 P-256 密钥，私钥留在工牌内部 |
| 被动 NFC 标签 | 保存 NDEF 账户入口，供外部读卡端读取 |
| 外部 NFC 终端 | 建立单据，读出入口并请求发起成员确认 |
| 本地桥接端 | 获取完整事项，把工牌签名送给社区服务 |
| 社区服务与账本 | 核验权限、签名和版本，原子记账，返回结果 |

FoloToy AI Passport 的现有被动 NFC 标签不能被当成 MCU 可读写余额存储器。使用前须核对目标硬件批次的 [官方设计资料](https://github.com/FoloToy/ai-passport/tree/main/docs/hardware-design)。不能假设一次外部 NFC 碰卡会直接唤醒固件或把议题送上工牌。

## 设备内最小状态机

接收完整请求后，显示具体正文、分值或执行内容、版本和期限。用户通过上/下键选择该事项允许的回复，OK 进入复核页；在复核页完整长按两秒后才签名。返回、提前松手、换事项、内容改版或超时取消本次按住动作。

工牌核对社区、成员和协议版本，按 [签名帧约定](../docs/api.md) 构造 canonical UTF-8 数据。私钥签名，提交 `deviceId`、`decision`、单调 `counter` 和 P1363 签名。显示最终服务端结果前，不假定记账成功。

需要保存最后一次尚未得到结果的签名请求。断线后原样重试同一回复；不得换单号重放。服务端成功结果未返回时显示「结果待核对」，由查询或相同签名重试恢复。设备掉电后计数器不得回滚；跳号可接受。

BLE 必须单独设计安全配对、成员会话、长度校验、分片、重连和传输认证。签名帧防止内容被改后仍获验收，但不会自动提供 BLE 保密、设备发现或本人身份核验。

## 密钥与硬件验证

安全元件可以承载不可导出的设备私钥。仅使用 MCU 存储时需明确实际的 Secure Boot、Flash Encryption、调试口与恢复配置；不能仅凭 ESP32 型号或派生密钥宣称私钥不可导出。

测试真实按键防抖、提前松手、计时、低电量和掉电重试；确认屏幕展示的是实际签名内容。长文本需完整分页或明确的阅读流程，不能只给用户看摘要前八位。

## NFC 阶段

第一阶段使用普通 NDEF 标签，余额留在本地账本，断开账本时停止扣分。桌面读卡器可适配现有 `/api/nfc/scan`，但其驱动和权限尚未接入。

若后续确需在多个完全离线终端间刷出积分，需要安全 NFC 卡、相互认证、受保护的价值记录、交易计数和断电恢复协议，并处理撤销新鲜度及双花。普通标签上保存一个余额或签名余额快照不足以完成此功能。
