# 有界分片接收层（真实 BLE 尚待接入）

`passport_receiver` 与既有 `passport_transport` 使用相同 SP/1 包格式。它是纯 C、RAM 内的接收状态机，不是 NimBLE 配对、GATT 服务或身份认证实现；main.c 仍未接入网络或真实签名。

## 调用顺序

1. 可信本地 BLE 适配器完成加密、对端身份/角色验证和社区绑定后，分配从不复用的本地会话代数。不得从数据包或远端布尔值读取该代数；连接句柄本身可能复用，不能直接作为代数。
2. 串行任务以 `{0}` 初始化对象，调用 `passport_receiver_open`。packet_size 是双方预先约定的最大 ATT 特征值长度（ATT MTU 减三，最大512），不是 ATT MTU 本身；打开期间不得改变。默认 MTU 23 的20字节包仍可工作。
3. 把属于该会话的完整特征值交给 receive；单个包超长、CRC失败、空正文、乱序、跨传输号、总数变化或不同字节的重复片会清空整个半包。非末片必须用满约定长度；只允许最近一片的完全相同副本，便于 ACK 丢失重试。只有 PARTIAL/COMPLETE/DUPLICATE 可以发对应 ACK。
4. 本地单调毫秒时钟必须持续驱动 tick；从 open 起的绝对超时最多30秒，片段和重复片不延长期限。时钟倒退或超时清空正文，完成但未消费的正文同样到期失效。旧会话迟到的数据和 tick 不得改变当前会话。断线、取消、输入队列溢出或认证失效须立即 close，清空半包和会话；重连以新代数重收完整消息。
5. 只有完整且未过期的消息能被 take 复制一次，输出缓冲区不足时保留至原截止时间。take 成功清空接收器；之后必须经本地调度显式打开新会话。对象、输入、输出及输出长度/ID指针不得相互重叠；操作不可重入。对象约4KB，实际任务栈/静态分配需由设备构建验证。
6. 复制的消息交给**独立的严格解析、来源和业务核验层**。该层仍须限制JSON/UTF-8结构、核对社区、成员、设备、挑战、有效期、内容摘要和类型；结果只能通过既有信任配置及服务签名验证后结清 outbox。接收完成、CRC、ACK和连接加密本身都不代表同意、签名可信或积分记账成功。接收器不调用签名器、不清除日志、不操作账本。

上限为4096字节、同时一条消息；超限不截断，不跳过部分正文继续让用户批准。现有回执发送仍由delivery负责，不能用接收器绕过其“先持久化再发送”约束。接收器没有全局重放缓存：已消费的消息可能在新会话再来，业务幂等、nonce/版本、计数器和签名核验仍不可省略。最终片 ACK 丢失而接收器已消费时，本批未实现已完成传输缓存；适配器必须处理有界最终ACK交付，或允许发送端重连重传原单并由业务幂等核对。

## 验证与剩余边界

主机测试与现有 sender 互通，覆盖20/512字节包、4096边界、ACK丢失、原片重发、迟到旧会话、重连半包隔离、乱序、冲突副本、CRC/长度错误、最大分片数、空正文、超长末片、绝对超时和倒退时钟。构建安装脚本与CMake包含新源码；CI中的test:firmware-host运行接收测试。

本批未实现真实配对、GATT权限、发送/接收适配器、定时任务、事件队列或严格请求解析器；不能把此模块称为“认证蓝牙已完成”。没有ESP-IDF工具链或USB工牌，交叉编译和真实BLE/NVS/按键/屏幕/NFC测试均未运行。下一步应先落实可信对端身份及GATT安全策略，再接实际事件与调度；不能通过把authenticated设为true来代替认证。
