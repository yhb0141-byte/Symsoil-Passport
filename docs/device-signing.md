# 设备签名协调器与计数器

本批交付纯C的 `passport_signer`，将已确认事项、签名提供者和现有持久化交付层连起来。OpenSSL主机测试每次临时生成真实P-256软件密钥并验证签名；设备上尚无私钥生成、受保护存储或签名后端，也没有将该模块接入 `main.c`。默认验收固件仍只记录合成按键事件。

## 调用边界

只有可信本地任务可以调用 `passport_signer_submit`。调用前必须完成当前事项全文阅读、独立回复选择、版本/摘要/nonce/到期检查及最终连续长按。签名器不是用户确认界面，不能从BLE包、远程布尔字段或未经核对的旧事件直接调用。由该任务保证输入字符串在同步调用期间不可变；所有存储、签名、交付和UI事件必须在同一任务或同一互斥区内串行执行，不能依赖 `active` 标志作为线程锁。

`confirmed_frame.counter` 必须为0，由模块独占分配。其他字段按 `symsoil-passport/1` 编码，回复字符串保持原值，不将decline、needs_change或original_only变成approve。可信时钟、对成员/设备的登记绑定、服务请求新鲜度和撤销核对仍由集成层与社区服务负责；本模块不构造这些信任事实。

提供者接收canonical UTF-8字节，应对SHA-256摘要完成P-256签名，输出64字节P1363，不输出DER，不重复哈希。接口不包含私钥字段。后续安全元件后端可在芯片中签名；软件开发后端必须明确标识可导出私钥的风险，不能伪装成硬件保护。

## 持久化顺序

1. 以 `0x04 || publicX || publicY` 的SHA-256绑定计数器身份；公钥必须由可信登记流程提供，不接受链路自选身份。
2. `passport_counter_enroll` 只在专用存储两槽均不存在时执行。起点来自可信本地登记；已有、损坏或单槽残留不会被自动清零。
3. `passport_counter_open` 要求两槽长度、身份、版本、保留字段、CRC和值完全一致，且不低于独立可信下限。没有有效记录时不自动新建。
4. 每次reserve先重读并核对RAM中的高水位，再将下一个计数器分别写入两槽并逐槽读回。全部成功才调用签名提供者；任何不确定失败锁定当前句柄。计数器以JavaScript安全整数上限为界，不回绕。
5. 成功或失败的签名都不退回已占用计数器。提供者错误或签名与登记公钥不符，不进入outbox。
6. 成功签名先留在RAM，交给原交付协调器保存。保存成功才开放首包；保存失败返回NOT_DURABLE并保留原签名。新的submit返回BUSY；只用retry_save重试原字节，不调用提供者、不再占用计数器。失败恢复先重新打开durable outbox，不清除另一笔记录或损坏记录。
7. 持久化后掉电，从原outbox恢复同一签名、封装和transferId。ACK不能清除；仍须验证社区签名的业务结果。

计数器存储复用 `passport_outbox_store_t` 的读写回调，但必须使用独立的命名空间/键，绝不能与outbox或服务信任两槽混用。ESP-IDF已有NVS适配器可用独立namespace承接此接口；本批未在真实NVS上执行该路径。

## 掉电与回退边界

- 写入第一份计数器后掉电、镜像写失败或两份分歧：锁定，停止签名，不择较小值继续。
- 计数器已持久化但签名失败或签名前掉电：跳过该计数器。服务允许严格递增而不要求连续，不回填空洞。
- 签名已生成但outbox完全未落盘即掉电：签名可能丢失，保留计数器空洞，不能宣称原交易已送达。重新核对服务事实后，必要时重新读取当前事项并由成员再次确认；绝不后台自动再签。
- outbox至少一份有效且已落盘：由原日志恢复精确字节。存储错误未恢复前不发送新签名；损坏或其他占用保持阻断。
- 普通Flash的CRC不是认证，也不能证明新鲜度。两槽完全一致的旧镜像在重启后仍可能通过本地检查。测试明确展示：提供独立可信高水位可以检出；低下限无法检出。不能声称本模块提供硬件防回滚或不可导出密钥。
- 部分写入后的恢复必须通过可信维修/重新登记程序，选择独立可信高水位或换设备身份；本批不提供远程清零/自动修复接口。真实生产还需安全元件、受保护单调计数器/可信外部高水位、设备登记和撤销策略。

## 可复现验证

`npm run test:firmware-host` 包含临时真实OpenSSL P-256签名、自验、公钥身份错配、decline原语义、先占用计数器、提供者失败/错签、outbox首槽/镜像失败、原签名重试、重启恢复、计数器分歧/旧镜像回退/可信下限、陈旧句柄、读回损坏和整数耗尽。测试不输出私钥、不写入真实账户或凭证。

本批73项Node回归、全部主机测试、Python固定向量核验、签名模块GCC静态分析及签名集成测试ASan/UBSan通过；LeakSanitizer未运行。设备构建、BLE、真实按键、真实NVS和NFC未测试，未以历史构建代替本批证据。浏览器流程本批未重复运行（上批环境缺Chromium且下载失败，本批没有Web界面变更）。
