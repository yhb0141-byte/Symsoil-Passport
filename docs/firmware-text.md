# 工牌中文分页基础层

`passport_text` 是本地纯C分页器，尚未连接main.c、LVGL字体或签名入口。它解决“字节截断、缺字替换、后半段消失”这一部分问题，不解析请求JSON、不认证来源，也不证明成员看到了全部交易语义。

## 使用边界

1. 可信解析器必须从review拥有的canonical原文中提取并核对全部有意义字段，包括社区/成员/请求/版本/有效期、积分方向和数额、工具或授权对象与限制。不能仅分页远程提供的标题，也不能信任远程page_count。此解析器尚未实现。
2. 把完整、明确的本地展示文本交给 `passport_text_open`。原文在调用期间稳定，不能与输出对象重叠。模块保存所有页，不保留输入指针；调用后输入变化不会修改已布局页面。所有调用串行、不重入；对象约9KiB，避免放进小任务栈。
3. `has_glyph` 必须查询**实际选用字体**中的字形，不能无条件返回true或接受问号替代。当前布局是固定字格模型：ASCII一格、汉字/全角两格，columns为格数。字体实际宽度、字号与显示区域必须一致；比例字体需要另写像素布局，不能套用本模块。
4. 所有字符检查完且返回OK后才能开始渲染。输入最长4096字节，最多128页；列数2–80、行数1–40。超限或任一处失败清空所有页，不能先展示前几页再略过末尾。缺字返回MISSING_GLYPH及码点；必须阻止进入确认，可提示“当前字体缺字，请更换显示终端”。不能用替代字符继续签名。
5. `passport_text_page` 仅复制完整页，容量不足清空输出并返回false。页号从0开始；自动换行不拆UTF-8字符，显式空行保留，末尾换行可能产生空白末页。严格按实际页面数展示后，再通知review读页；该步骤仍待可信UI接线。
6. 页面作为纯文本显示。LVGL recolor/markup必须关闭，不能把`#ff0000`等文本当指令；关闭二次自动换行，以匹配当前字格布局。字距、行距、尾部空行及溢出策略须在真实屏幕检查。重布局/字号变化/展示内容改动应取消旧review、重新阅读，不能复用此前页数和长按。

UTF-8解析拒绝过长编码、截断、多余续字节、代理项和超出Unicode范围的码点。第一版只支持可打印ASCII、LF、CJK标点（排除组合声调）、扩展A/基本汉字及全角ASCII；控制符、NUL、CR、TAB、双向/零宽格式字符、组合字符、emoji及其他文字返回UNSUPPORTED，整个展示失效。此范围是明确限制，不是完整Unicode支持。原签名正文不被归一化或改写。

## 验证与未完成项

`firmware/folotoy/test-host.sh` 编译运行中英文混排、数字与标点、显式空行、源缓冲区变化、页面复制容量、缺字出现在后页、非法UTF-8及控制字符、4096字节和128页边界、10000组确定性随机字节用例。测试字体覆盖回调为合成替身，不是生产字体。新模块另经GCC静态分析和ASan/UBSan检查。

真实中文字体子集、字体许可证与生成流程、LVGL字形回调、请求解析、页面到review的完整绑定、ADC键位/显示集成尚未完成。没有进行本批ESP-IDF交叉编译、实物屏幕/缺字/换行验证。不能以纯C主机测试宣称中文工牌界面已经可用。
