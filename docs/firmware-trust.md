# 工牌服务公钥的配置、轮换与恢复

本批实现的是可在主机测试的固件信任层，以及它与回执交付协调器的连接。它尚未接入真实工牌的配置页面、BLE或私钥签名。服务器已加入可选的历史回执签名结果接口，见 [签名结果](delivery-results.md)。公开合成向量不能用于生产配置。

## 两种钥匙

- **恢复根公钥**：由可信固件构建或受控的本地交接提供。`passport_trust_open` 接收固定社区 ID 和根公钥；NFC/BLE 消息不能提供或替换这个根。对应私钥由社区独立保管，不放入工牌，也不交给日常交易服务。
- **服务公钥**：用于核验 `symsoil-delivery-result/1` 的业务结果。根私钥签发服务公钥配置，并给每一版配置分配严格递增的 `epoch`。根密钥不能同时充当服务密钥。

新增 `passport_provision` 状态机提供完整根指纹核对、独立最终长按、超时/取消和一次性提交；真实按键与屏幕尚未接入。这里的“本地确认”仍是可信事件来源的集成前置条件，不是已经完成的物理按键验证。调用方必须在独立核对完整根公钥指纹后，执行受控本地操作。不能把 BLE 正文中的 `locally_confirmed: true` 直接传给该接口，不能用首次收到的网络公钥自动建立信任。根公钥更换尚无在线 API；丢失根私钥需要另行设计重新交接流程。

根指纹为未压缩 SEC1 公钥 `04 || X32 || Y32` 的 SHA-256 十六进制摘要。签名工具可计算指纹，但可信指纹必须从独立渠道核对。

## 配置生命周期

| 当前状态 | 操作要求 | 结果 |
| --- | --- | --- |
| 未配置 | 固定根签名、非零 epoch、本地确认 | 写入第一份有效配置 |
| 正常或已停用 | 固定根签名、严格更大的 epoch | 轮换服务钥匙、停用或恢复服务 |
| 存储锁定 | 固定根签名、本地确认、独立获得的权威 epoch 下限 | 以高于下限及所有已观察有效记录的 epoch 恢复 |
| 任意状态 | 旧版本、错误签名、错误社区、混用根与服务钥匙 | 拒绝，保留待核对交易 |

停用也是一份根签名配置，状态为 `suspended`，服务公钥坐标为零。它不删除历史回执，也不自动撤销服务器已经受理的交易。恢复后的当前服务可以为同一原成员签名重新提供签名结果，无需让成员再次批准。服务器现在可为已保存的同一原回执出具签名结果，默认需显式配置后启用。

`epoch` 为非零 uint32；用完 `4294967295` 后不能归零继续使用，需要迁移方案。签名工具只签署给定 epoch；权威签发方还须维护独立的签发记录，不能给同一社区的同一 epoch 签发冲突配置。

## 双槽存储与掉电

复用 `passport_outbox_store_t` 的读写接口，但使用**独立命名空间**，例如 `sp_trust`，不能使用保存待发回执的命名空间。现有 NVS 适配器可在该命名空间保存 `outbox0`、`outbox1` 两个 blob；两个业务模块的 NVS 句柄及存储对象必须分别创建。

信任配置与回执恢复采用不同策略：两份配置都必须存在、根签名有效且字节完全一致，才能使用服务公钥。某份缺失、损坏、读写失败或两份不一致时，进入 `LOCKED`。不能只挑一份旧的有效配置继续交易，以免停用写入中断后重新启用旧钥匙。

写入顺序为第一槽写入和读回核对，再写第二槽和读回核对。失败后当前实例锁定，不开放服务公钥。重新打开时只接受两份完整、一致且有效的记录，否则必须走本地恢复；未成功持久化的停用不能宣称已经生效。选择服务公钥时重新读取、验证两份配置。所有操作由单一任务串行调用；接口不是并发事务锁。

恢复需要独立核对权威 epoch 下限；不能因读不到存储就假定下限为零。设备会记住本进程观察过的最高有效 epoch，但 NVS、CRC 和普通 Flash 不能防止重启后的完整旧备份回滚。生产版还需可信启动、合适的存储保护和硬件或外部可信版本下限。两槽损坏时同样无法自行推导真实历史下限。

## 已签名交易不随配置改变

`passport_delivery_finalize_signed` 只接收信任管理器和服务签名，不再接收链路提供的公钥。它从当前有效配置选择服务公钥，再校验签名、社区、传输号和完整原成员签名。未配置、停用或锁定状态不能清除待发回执；旧服务钥匙在轮换后立即不再被本管理器接受。

轮换、停用、恢复只改信任存储，不改 outbox 的成员签名、原帧、计数器或传输号。没有收到已验证的最终业务结果，界面必须保持“结果待核对”。

## 签名格式 symsoil-trust/1

这里采用固定字段顺序的二进制帧，不是 JSON；多字节整数为小端。

| 字节位置 | 内容 |
| --- | --- |
| 0–15 | ASCII `symsoil-trust/1`，末尾一个 NUL，共16字节 |
| 16 | 状态：1=active，2=suspended |
| 17 | 社区 ID 字节数，1–64 |
| 18–19 | 保留位，必须为零 |
| 20–23 | 非零 epoch，uint32 LE |
| 24起 | 社区 ID，ASCII `[A-Za-z0-9:_-]` |
| ID之后 | 服务公钥 X32、Y32；停用时64字节全零 |

帧长为 `88 + 社区ID长度`，最多152字节。根使用 ECDSA P-256/SHA-256 签署完整帧，签名为64字节 P1363。存储记录为帧、签名和4字节 CRC32 LE，最多220字节；CRC不代替签名。Node 工具还验证服务公钥是否为合法曲线点；设备在使用该公钥验证结果时也会核验曲线点。

## 离线签发工具

准备一份配置 JSON，例如：

```json
{
  "communityId": "jiuhua-symsoil",
  "epoch": 1,
  "state": "active",
  "servicePublicKey": {
    "kty": "EC",
    "crv": "P-256",
    "x": "替换为真实公钥X坐标的base64url",
    "y": "替换为真实公钥Y坐标的base64url"
  }
}
```

停用配置用更高 epoch、`"state": "suspended"` 和 `"servicePublicKey": null`。示例坐标是占位文字，不能直接签发。

```sh
node scripts/trust-config.mjs sign \
  --manifest /secure/community-manifest.json \
  --authority-private /secure/authority-private.jwk.json \
  --out /secure/new-public-bundle.json

node scripts/trust-config.mjs inspect \
  --bundle /secure/new-public-bundle.json \
  --authority-public /secure/independently-pinned-authority.jwk.json
```

工具仅读取指定私钥，在内存签名，输出公开配置包，不输出私钥，不覆盖已有输出，也不自动写入工牌。私钥、真实配置和个人数据不得提交 Git。`inspect` 必须提供单独的可信根公钥；配置包里附带的根不能自行声明可信。密码验证通过不代表版本可被设备接受，也不代表持有人身份已确认。

## 验证与下一步

- `npm test`：签名工具、输入验证、CLI、公开向量与已有业务测试。
- `npm run test:firmware-host`：纯C状态/故障测试，以及使用 OpenSSL 3 的真实 P-256 信任与交付互验；需要 C 编译器、Node 24 和 OpenSSL 3 开发头文件/库。
- `python3 scripts/verify-protocol.py`：独立核对确认、结果与信任向量；需要 Python `cryptography`。

主机互验覆盖：首次配置、轮换、停用、恢复、错误签名、旧钥匙拒绝、镜像写失败、掉电重开、回执字节保持以及新钥匙结清原回执。故障测试中的密码替身与 OpenSSL 实算法测试分别保留。

当前没有 ESP-IDF 5.5.3 工具链，也没有真实工牌或 NFC 标签。本批未进行设备交叉编译、刷机或实物验证。下一步先完成受控配置页面与固定根的交接，再连接真实设备私钥、认证 BLE 与已实现的服务器签名结果；不能仅凭本模块宣称已完成生产配置。
