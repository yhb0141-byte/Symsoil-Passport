## 下一批优先顺序

1. 完成固定恢复根的受控交接、本地配置页面与权威epoch签发记录，再让BLE接收路径调用已有信任层；物理确认与版本下限不能来自链路正文，合成向量不能成为生产密钥。
2. 在设备安全边界明确后加入不可导出的私钥生成/保护、设备登记和 P-256 签名，把签名成功后的唯一回执交给现有协调器；不得把公开测试向量、NFC UID 或可导出的浏览器私钥当作设备身份。
3. 实现经过认证的 BLE 配对、GATT 收发和超时调度，以现有协调器作为唯一发送入口；签发方可信公钥锚与撤销新鲜度必须独立说明，不能把短期限说成即时撤销。
4. 加入最小中文字体子集与缺字回退；有真实设备和明确刷机授权后，再执行屏幕、ADC、提前松手、功耗和低电量验收。

## 约束

- NFC 标签只保存账户引用，不相信标签余额或 UID；后端不可达时停止扣分。
- 查看、沉默、表达准确、原话许可、任务承担和正式批准不可合并。
- 积分不购买治理权限或基本服务；无人民币充值、提现或个人转账。
- 凭证、数据库、个人导出、浏览器截图、私钥不提交 Git。协议测试材料只使用明确标注的合成公钥与签名。
- 核验历史签名不代表本人身份、签发方可信或当前授权未撤销。
