## 下一批优先顺序

1. 提交结果丢失时保留已签名的回复，明确区分「服务端拒绝」和「结果待核对」；重连只重发原签名，不替成员重新批准。
2. 固定的硬件签名协议向量：canonical UTF-8、内容摘要、P-256 公钥、P1363签名；独立语言验证和篡改案例。
3. 成员收件箱自动同步，过期与改版提示，保持长按中途取消和不打断用户阅读。
4. 核对 FoloToy 官方引脚与固件基线，再决定可编译的硬件原型范围；没有实物时只能报告编译和协议验证。
5. 签发方签名的有限授权封装与可信公钥锚；需要讲清离线撤销新鲜度，不能把短期限说成即时撤销。

## 约束

- NFC 标签只保存账户引用，不相信标签余额或 UID；后端不可达时停止扣分。
- 查看、沉默、表达准确、原话许可、任务承担和正式批准不可合并。
- 积分不购买治理权限或基本服务；无人民币充值、提现或个人转账。
- 凭证、数据库、个人导出、浏览器截图、私钥不提交 Git。协议测试材料只使用明确标注的合成公钥与签名。
- 核验历史签名不代表本人身份、签发方可信或当前授权未撤销。

## 每批检查

运行 `npm run check`、`npm test` 与适用的 `npm run test:ui`，核对完整变更、文档与硬件边界。通过后提交到原开发分支，更新草稿 PR 描述。记录实际证据、环境限制和下一步。达到窗口截止只汇总，不再开新工作。
